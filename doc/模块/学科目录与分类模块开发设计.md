# 学科目录与分类模块开发设计

> 本文档针对 408考研真题知识点阅读网站中的学科目录与分类模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。

---

## 1. 需求

### 1.1 模块目标

学科目录与分类模块解决题库内容缺少稳定学习上下文的问题。它以科目为一级入口，提供章节数据和真题分类树，并为真题、模拟题、题库维护、统计和收藏提供统一的科目/分类选择边界。

**已确认事实**：项目有 `Subject`、`Chapter`、`ExamCategory` 三类目录实体；科目和真题分类在管理员页面维护，章节后端已有 CRUD 和树查询但当前没有独立前端管理页面；模拟题侧边栏和管理页的分类主要从模拟题 JSON 分类字段动态汇总。

**事实冲突**：`ExamCategory` 名称虽然是“真题分类”，分类 API 的 `question_type` 同时接受 `exam`、`mock`、`exercise`，但当前 `exercise` 没有对应题目实体和独立业务闭环。模拟题还存在两条不完全一致的目录路径：管理页从模拟题 JSON 动态生成临时分类，学习页复用分类树接口并从持久化 `ExamCategory` 节点补充模拟题数量；本文档只把 `exam` 和 `mock` 作为当前有效范围，并将模拟题目录源统一列为设计事项。

**设计假设**：继续使用现有分类 JSON 文本与分类名称匹配方式，不在本次文档范围内新增题目-分类关联表；若以后要求强引用完整性，再单独进行数据模型设计。

**分类编码规则**：`ExamCategory.code` 由服务端自动生成层级编码，格式为“科目拼音首字母-同级编号-分类拼音首字母”，多级分类继续追加同样的编号和首字母段，例如 `sjjg-01-xxb-01-sxb`。新增分类不要求管理员手填编码；名称修改不重算编码，父分类移动时当前节点及其子树的路径编码同步更新，`order_num` 只负责展示排序。

### 1.2 功能需求

| 编号 | 需求 | 可观察行为 |
|---|---|---|
| DIR-01 | 科目展示 | 学习者看到启用科目及真题数量；管理员可查看全部科目，包括禁用项。 |
| DIR-02 | 科目维护 | 管理员可创建、编辑、启用/禁用和删除科目；名称与编码重复时操作失败。 |
| DIR-03 | 章节树 | 调用方可按科目读取启用章节树；管理员调用方可读取完整章节树并维护章节。 |
| DIR-04 | 真题分类树 | 学习者和编辑器可按科目读取分类树或启用分类；管理员可维护真题分类的父子层级、自动编码、排序和状态。 |
| DIR-05 | 模拟题分类 | 模拟题浏览与统计可根据题目中的分类 JSON 动态生成分类和数量，不提供与真题分类相同的手工新增入口。 |
| DIR-06 | 引用检查 | 删除真题分类前能看到子分类、真题引用和模拟题引用，并阻止有子级或引用的删除。 |
| DIR-07 | 统计维度 | 分类树节点可显示对应题型的题目数量；多分类题目在总量统计中按题目去重。 |

### 1.3 非功能需求

- **一致性**：分类、父分类和题目所属科目必须一致；父节点变更不能产生自引用或循环引用。
- **安全**：公开读取只返回启用目录（管理读取除外）；创建、编辑、删除和全量读取需要管理员权限；服务端不得仅依赖前端隐藏按钮。
- **性能**：学习端分类树查询应限制在指定科目；分类统计不能为每个页面重复拉取无关科目；当前实现存在逐分类统计查询和内存建树，目录规模增大时需要关注 N+1 查询。
- **可靠性**：分类名称重复、父节点不存在、父节点跨科目、删除有子级或有引用时，均应返回稳定的 404/409 业务语义；层级编码由服务端生成并由唯一索引兜底。
- **可用性**：目录列表、树、空数据、加载失败和禁用状态必须可区分；编辑器在历史题目包含未定义分类时不能静默丢失该分类文本。

### 1.4 范围、边界与不做项

- **本模块负责**：科目、章节、真题分类的目录数据和模拟题动态分类读取；层级、启用、排序、引用检查及目录相关统计。
- **题库内容模块负责**：题干、选项、答案、题型、难度以及题目中的分类 JSON 内容。
- **统计模块负责**：跨范围统计和导出；本模块只提供分类树需要的局部数量。
- **不做项**：章节独立前端管理页面、课后习题实体、单题收藏、分类重命名后的历史题目批量迁移、题目-分类规范化关联表和用户自定义分类。

### 1.5 验收标准

1. 启用科目查询按 `order_num` 返回，管理员全量查询包含禁用科目；分类名称重复无法创建或更新，系统生成编码保持科目内唯一。
2. 指定科目的章节树和分类树层级正确，节点按 `order_num` 排序，启用查询不包含禁用节点。
3. 创建/移动分类或章节时，跨科目父节点、自身父节点和不存在父节点均被拒绝；同一科目同一父节点下名称重复返回冲突。
4. 真题分类删除前若存在子分类、真题引用或模拟题引用，删除被拒绝；无引用叶子分类删除后不再出现在目录读取结果。
5. 模拟题模式不会出现手工新增分类按钮对应的可用写接口，分类数量来源于模拟题实际分类数据。
6. 分类统计中一题多分类不会增加去重总题数；前端切换科目或题型后不会显示旧目录数据。

## 2. 该项目的模块结构与流程

### 2.1 项目级关系

| 方向 | 当前项目边界 | 协作内容 |
|---|---|---|
| 上游 | 管理员科目/分类表单、题目编辑器 | 提供目录维护输入和题目分类选择。 |
| 后端入口 | `backend-fastapi/app/api/subject.py`、`chapter.py`、`exam_category.py` | 分别暴露科目、章节和分类的读取/维护边界。 |
| 业务处理 | `backend-fastapi/app/services/subject_service.py`、`chapter_service.py`、`category_service.py` | 执行唯一性、父子关系、树构建、空分类过滤和引用统计。 |
| 数据访问 | `backend-fastapi/app/repositories/subject_repository.py`、`chapter_repository.py`、`category_repository.py`、`app/database/connection.py`、`backend-fastapi/app/models/entities.py` | 通过各领域 Repository 访问 `subject`、`chapter`、`exam_category` 及题目表的统计数据。 |
| 学习端调用方 | `frontend/src/components/business/SubjectSidebar.vue`、`frontend/src/views/user/ExamClassify.vue`、`MockClassify.vue` | 加载科目和按题型过滤的分类树。 |
| 管理端调用方 | `frontend/src/views/admin/SubjectManage.vue`、`CategoryManage.vue` | 维护科目和真题分类；模拟题分类只展示动态汇总。 |
| 下游模块 | 历年真题学习、模拟题学习、题库内容维护、统计与导出、收藏 | 使用目录作为筛选、分组、统计或跳转上下文。 |

### 2.2 当前代码边界与规范冲突

当前后端采用 Router → Service → Repository → Schema/Model 的横向结构。分类服务使用 `CategoryRepository` 查询并将扁平结果在内存中构建任意深度树；章节服务按简单两级结构组装树，模型虽支持自引用，孙级节点是否完整返回需以实现核验；题目分类保存在 JSON 字符串中，引用检查通过包含名称的字符串匹配完成。

前端 `useSubjects`/`stores/subjects.ts` 负责启用科目缓存；`SubjectSidebar.vue` 展示科目和树；`useQuestionForm.ts` 同时加载扁平分类和树分类，并把历史未定义分类临时加入编辑选项；`CategoryManage.vue` 在真题模式使用持久化分类，并通过 `useCategoryDrag.ts` 提供手柄拖拽、多级移动、同级排序与松手自动保存，在模拟题模式把统计结果转成前端临时节点；`MockClassify.vue` 当前则调用带 `question_type=mock` 的共享分类树接口，实际依赖该接口返回的 `ExamCategory` 节点。

**当前契约**：科目、章节和分类的查询、树、统计及写入路由均使用 POST + Request Schema；前端 `api/subject.ts`、`category.ts` 统一通过 `request.ts` 调用，出站字段使用 snake_case，响应字段转为 camelCase。第 4 节仍保留目标路径命名示例，不能与当前路由混用。

### 2.3 核心流程

```mermaid
flowchart LR
    A[管理员维护科目] --> B[建立章节与分类层级]
    B --> C[题目选择科目与分类]
    C --> D[题库存储题目上下文]
    D --> E[学习端读取目录树]
    E --> F[按目录筛选题目]
    B --> G[引用与数量统计]
    G --> H[删除前风险判断]
```

### 2.4 数据流与状态流

1. 管理员表单产生 Subject/Chapter/ExamCategory 写入请求，Pydantic 负责类型、长度和范围校验，Service 负责父节点归属、同级唯一性和层级编码生成。
2. 数据库保存科目和层级目录；题目表只保存 `subject_id` 与分类名称 JSON，不保存分类外键关联。
3. 学习端读取启用科目和分类树；真题树的数量来自 `ExamQuestion`，模拟题统计数量来自 `MockQuestion`。当前模拟题学习页通过共享分类树接口获取节点，管理页则可直接从 `MockQuestion.category` 动态生成临时节点，二者数据源并未完全统一。
4. 前端把服务端 snake_case 响应集中转换为 camelCase，树组件只消费 `children`、`name`、`orderNum` 和数量等领域字段。
5. 分类删除先做引用/子级检查；删除分类不会回写历史题目的分类 JSON，因此历史题目可能保留“未定义”分类文本。
6. 当前没有后台任务、缓存失效广播或事件总线；目录更新后的刷新由调用页面主动重新读取完成。

### 2.5 异常、并发、事务和一致性

- **参数错误**：`subject_id`、`parent_id`、名称、排序和启用字段由对应 Pydantic Schema 校验；分类编码不属于管理员输入字段；校验异常统一为 422。
- **资源错误**：不存在的科目、章节、分类或父节点返回 404；当前服务部分场景使用 `NotFoundException`。
- **冲突错误**：同名、生成编码冲突、跨科目父节点、自身父节点、存在子级或题目引用返回 409。
- **并发写入**：分类名称和编码由 Service 预检查，并由 `ExamCategory` 的 `(subject_id, name)`、`(subject_id, code)` 唯一索引兜底；分类写入口还通过 `_lock_structure` 在读取层级前取得 SQLite 写锁，锁竞争（BUSY/LOCKED）映射为 409 `ConflictException` 并提示刷新重试，防止并发移动基于过期树校验。
- **事务**：`CategoryCommandService` 拥有分类创建/更新/移动/删除用例的事务并显式提交，`get_async_session` 在异常时回滚并关闭；新增/更新/移动/删除一个目录节点由一个请求事务拥有，不要在树构建、统计或 Repository 辅助方法中提交。
- **删除与外键**：当前连接已显式开启 SQLite 外键；Subject 关系和高优先级迁移为章节/分类配置级联，题目 `subject_id` 配置为删除时置空。科目删除入口仍应明确“禁用”优先还是“删除级联”优先，不能只依赖数据库默认行为。
- **重试**：读取树和统计可由前端手动重试；目录写入和删除不能由客户端自动重放，按钮需防重复提交。

### 2.6 关键技术选择

- 继续使用内存建树：当前目录规模和任意深度树需求适合 O(n) 组装，避免引入递归 SQL；但应限制输入规模并避免逐节点重复统计。
- 继续保留 JSON 分类字段：这是当前题目响应和编辑器的既有契约，短期改成中间表会影响题目维护、统计、导出和历史数据；本设计不新增关联表。
- 对模拟题采用动态分类作为目标方向：管理页已明确禁用手工新增；建议学习页也直接从 `MockQuestion.category` 聚合，避免当前共享分类树对持久化 `ExamCategory` 节点的隐式依赖。该调整不新增表，但会改变模拟题分类树的调用边界。

## 3. 数据库的设计

### 3.1 数据库与连接

- **数据库**：SQLite，默认连接 `sqlite+aiosqlite:///./data/web408.db`。
- **Session**：通过 `SessionDep` 注入异步 `AsyncSession`，请求结束关闭；写 Service 显式提交，异常时回滚。
- **Schema 初始化**：应用启动调用 `SQLModel.metadata.create_all`；数据库保留历史 `schema_migrations` 记录但不再维护迁移脚本，当前仍没有完整通用迁移框架。结构变化按项目规则处理，删除/重建现有数据库必须先获授权。
- **连接现状**：`connection.py` 已设置 `check_same_thread=False`、WAL、`foreign_keys=ON` 和 busy timeout。
- **落地建议**：后续重点核验级联删除语义、锁冲突重试和查询计划；所有目录写用例由 Service/请求边界拥有事务，辅助查询只返回数据。

### 3.2 `subject` 实体

| 字段 | 类型 | 可空/默认 | 约束与用途 |
|---|---|---|---|
| `id` | `INTEGER` | 数据库生成 | `PRIMARY KEY`，来自 `BaseModel`。 |
| `create_time` | `DATETIME` | 非空；UTC 工厂默认 | 创建时间。 |
| `update_time` | `DATETIME` | 非空；UTC 工厂默认并 on update | 最后更新时间。 |
| `name` | `TEXT` | 非空 | 模型 `unique=True`；科目展示名。 |
| `code` | `TEXT` | 非空 | 模型 `unique=True`；稳定业务编码。 |
| `description` | `TEXT` | 可空 | 科目说明。 |
| `order_num` | `INTEGER` | 非空；默认 0 | 学习端和管理端排序。 |
| `enabled` | `BOOLEAN` | 非空；默认 `True` | 是否进入公开目录和编辑选择。 |

### 3.3 `chapter` 实体

| 字段 | 类型 | 可空/默认 | 约束与用途 |
|---|---|---|---|
| `id` | `INTEGER` | 数据库生成 | `PRIMARY KEY`。 |
| `create_time` / `update_time` | `DATETIME` | 非空；基类默认 | 生命周期时间。 |
| `subject_id` | `INTEGER` | 非空 | 外键 `subject.id`；章节所属科目。 |
| `parent_id` | `INTEGER` | 可空；默认 `NULL` | 自引用外键 `chapter.id`；空表示顶级章节。 |
| `name` | `TEXT` | 非空 | 同科目同父节点下由 Service 校验唯一。 |
| `order_num` | `INTEGER` | 非空；默认 0 | 同级排序。 |
| `enabled` | `BOOLEAN` | 非空；默认 `True` | 公开章节树是否展示。 |

关系为 Subject 1:N Chapter，Chapter 自引用形成父子树；现有数据库的 Subject/父节点级联删除来自历史结构修复，当前模型关系也声明了级联集合，实际删除入口仍需按业务确认影响范围。

### 3.4 `exam_category` 实体

| 字段 | 类型 | 可空/默认 | 约束与用途 |
|---|---|---|---|
| `id` | `INTEGER` | 数据库生成 | `PRIMARY KEY`。 |
| `create_time` / `update_time` | `DATETIME` | 非空；基类默认 | 生命周期时间。 |
| `subject_id` | `INTEGER` | 非空 | 外键 `subject.id`；分类所属科目。 |
| `parent_id` | `INTEGER` | 可空；默认 `NULL` | 自引用外键 `exam_category.id`；空表示顶级分类。 |
| `name` | `TEXT` | 非空 | 当前 Service 按科目名称唯一性检查；题目 JSON 通过名称引用。 |
| `code` | `TEXT` | 非空 | 服务端生成的层级分类编码；由科目前缀、各级同级编号和各级名称拼音首字母组成，编辑器和管理端只读展示。 |
| `description` | `TEXT` | 可空 | 分类说明。 |
| `order_num` | `INTEGER` | 非空；默认 0 | 树节点排序。 |
| `enabled` | `BOOLEAN` | 非空；默认 `True` | 是否进入学习/编辑目录。 |

关系为 Subject 1:N ExamCategory，ExamCategory 自引用形成任意深度树。题目表没有 `category_id` 外键；删除分类前必须扫描真题和模拟题 JSON 文本。

### 3.5 索引、约束和生命周期

- 已确认索引与约束：Subject `name`、`code` 由模型声明唯一；`ExamCategory` 的 `(subject_id, name)`、`(subject_id, code)` 由模型声明唯一；现有数据库还保留章节/分类树查询的历史外键索引，重建数据库时需按查询计划重新评估。
- 推荐索引：若查询计划证明需要，可再评估 `chapter(subject_id, parent_id, order_num)`、`exam_category(subject_id, parent_id, order_num)`；不按字段数量堆叠索引。
- 当前约束口径：分类名称按科目全局唯一，编码按科目全局唯一；名称由 Service 校验，编码由 Service 自动生成并由唯一索引兜底。若产品要改为“同父级唯一”或允许跨层级同名，需先确认后再调整约束与校验。
- 状态生命周期：科目/章节/分类从启用开始，可被禁用；禁用不删除历史题目引用。删除只适用于无子级、无引用的分类；科目删除当前服务未检查题目引用，迁移外键会将题目的 `subject_id` 置空并保留题目内容，但会丢失科目归属，设计上应优先确认是否阻止有题目引用的科目删除。
- 统计与导出均为派生读取，不单独持久化目录统计快照。
- 备份、脱敏和隐私：目录本身不是敏感数据；备份须与题目数据库一并保护。目录删除不应删除题目内容，除非另有明确授权。

### 3.6 事务与直接重建策略

目录创建/更新/移动/删除由一个写 Service 事务拥有，先完成父级、同级唯一性和引用检查，再写入或删除；创建时自动生成编码，父分类移动时重建受影响子树的路径编码；树查询和统计只读。分类写入口在读取层级前通过 `_lock_structure` 取得 SQLite 写锁，锁冲突映射为 409；管理端仍需避免重复提交。当前数据库仅保留历史 `schema_migrations` 记录，没有迁移脚本或完整通用迁移框架；现有开发数据库已在保留分类层级和题目数据的前提下完成一次性编码整理，不执行删除或重建。

## 4. API 接口的设计

### 4.1 当前已实现边界（事实）

- 实际公共前缀为 `/api`，路由模块位于 `backend-fastapi/app/api/`，没有 `/api/v1` URL 段。
- `subject.py`、`chapter.py`、`exam_category.py` 的查询、树、统计和创建/更新/删除接口当前均使用 POST；前端对应 API 模块统一使用 JSON Body 和字段转换。
- 当前统一响应为 `ApiResponse[T]`：`{code: 200, message, data}`；分类树、章节树和列表大多直接放在 `data` 数组中。
- `check_category_usage` 当前响应声明为 `ApiResponse[int]`，而 Service 已有更丰富的 `ExamCategoryUsageResponse` 结构但路由未使用；这是已确认的契约缺口。

### 4.2 目标方法与统一响应

本设计的新增/改动接口全部使用 POST。查询、列表、树和统计的筛选均进入 Request Schema JSON Body，不使用 Query 参数；当前统一响应已使用 `ApiResponse[T]`，列表使用 `ApiResponse[PaginatedResponse[T]]`、字段 `lists` 与 `pagination`。目录当前没有分页需求，树/科目等小集合可使用 `ApiResponse[List[T]]`；若集合增长到需要分页再增加分页接口。

### 4.3 科目接口

| 名称 | 目标路径 | 请求 Schema / 输入 | 成功响应 | 鉴权、错误与幂等 |
|---|---|---|---|---|
| 查询启用科目 | `POST /api/subject/query-enabled` | `SubjectListRequest`（可为空对象） | `ApiResponse[List[SubjectResponse]]`，按 `order_num` 排序并带真题数量。 | 公开；数据库失败为 5xx；只读可手动重试。 |
| 查询全部科目 | `POST /api/subject/query-all` | `SubjectListRequest` | `ApiResponse[List[SubjectResponse]]`。 | ADMIN；无 Token 401、非管理员 403。 |
| 查询科目详情 | `POST /api/subject/query-detail` | `SubjectDetailRequest { subject_id: int }` | `ApiResponse[SubjectResponse]`。 | 公开；不存在 404。 |
| 按编码查询科目 | `POST /api/subject/query-by-code` | `SubjectCodeRequest { code: str }` | `ApiResponse[SubjectResponse]`。 | 公开；不存在 404。 |
| 创建科目 | `POST /api/subject/create` | 现有 `SubjectCreateRequest`：`name`、`code`、`description`、`order_num`、`enabled`。 | `ApiResponse[SubjectResponse]`。 | ADMIN；重复名称/编码 409；不自动重试。 |
| 更新科目 | `POST /api/subject/update` | `SubjectUpdateRequest` + `subject_id`；部分更新使用 `exclude_unset`。 | `ApiResponse[SubjectResponse]`。 | ADMIN；不存在 404，名称/编码冲突 409。 |
| 删除科目 | `POST /api/subject/delete` | `SubjectDeleteRequest { subject_id: int, confirm: bool }`。 | `ApiResponse[None]`。 | ADMIN；设计上题目/子目录有引用时 409；操作不可逆。 |

`SubjectCodeRequest` 已在当前编码查询路由中使用；`SubjectListRequest`、`SubjectDetailRequest` 和 `SubjectDeleteRequest` 仍是目标契约示例，不代表当前已实现接口。新增或改动接口必须使用 Pydantic Model，不使用 `body: dict`。

### 4.5 分类接口

| 名称 | 目标路径 | 请求 Schema / 输入 | 成功响应 | 鉴权、错误与边界 |
|---|---|---|---|---|
| 查询真题分类 | `POST /api/exam-category/query-by-subject` | `CategoryQueryRequest { subject_id: int, enabled_only: bool = false }` | `ApiResponse[List[ExamCategoryResponse]]`。 | 公开；只读取持久化真题分类；`mock` 动态分类由模拟题模块提供。 |
| 查询启用真题分类树 | `POST /api/exam-category/query-tree` | `CategoryTreeQueryRequest { subject_id: int, with_stats: bool = true, enabled_only: bool = true }` | `ApiResponse[List[ExamCategoryTreeResponse]]`。 | 公开；按真题统计并过滤空节点。 |
| 查询分类详情 | `POST /api/exam-category/query-detail` | `CategoryDetailRequest { category_id: int }` | `ApiResponse[ExamCategoryResponse]`。 | 公开；不存在 404。 |
| 查询可选父分类 | `POST /api/exam-category/query-available-parents` | `AvailableParentCategoriesRequest { subject_id: int, exclude_id: int \| null }` | `ApiResponse[List[ExamCategoryResponse]]`。 | ADMIN；返回同科目所有层级的父分类选项（含禁用分类），排除自身及全部后代。 |
| 查询真题分类统计 | `POST /api/exam-category/query-stats` | `CategoryStatsRequest { question_type: Literal['exam'] = 'exam' }` | `ApiResponse[ExamCategoryStatResponse]`。 | 公开或按现有页面权限确认；真题总题数去重；模拟题统计由模拟题模块提供。 |
| 查询分类引用 | `POST /api/exam-category/query-usage` | `CategoryUsageRequest { category_id: int }` | `ApiResponse[ExamCategoryUsageResponse]`。 | ADMIN；返回子级、真题数、模拟题数和 `can_delete`。 |
| 创建分类 | `POST /api/exam-category/create` | `ExamCategoryCreateRequest`，管理员只提交科目、父分类、名称、描述、排序和状态，不提交编码。 | `ApiResponse[ExamCategoryResponse]`。 | ADMIN；父节点/科目不存在 404，名称或生成编码冲突 409。 |
| 更新分类 | `POST /api/exam-category/update` | `ExamCategoryUpdateRequest` + `category_id`，不允许手动修改编码。 | `ApiResponse[ExamCategoryResponse]`。 | ADMIN；自引用、跨科目、同名冲突 409；移动父分类时同步更新当前子树路径编码。 |
| 移动分类 | `POST /api/exam-category/{category_id}/move` | `ExamCategoryMoveRequest { target_id: int \| null, position: Literal['before','inside','after'] }`；`target_id` 为空时 `position` 必须为 `inside`（移至顶级末尾）。 | `ApiResponse[List[ExamCategoryResponse]]`，返回该科目最新分类及统计。 | ADMIN；目标不存在 404，跨科目、移到自身或自身子孙 409；原子移动整棵子树并重排受影响同级，同时更新受影响路径编码，不改写题目标签；不自动重试。 |
| 删除分类 | `POST /api/exam-category/delete` | `CategoryDeleteRequest { category_id: int, confirm: bool }`。 | `ApiResponse[None]`。 | ADMIN；有子级/引用 409；不改写历史题目分类。 |

API 层只负责依赖注入、Schema 校验、统一 `success()`/`error()` 构造和 `response_model`；Service 只返回目录数据或抛出业务异常，不返回 `ApiResponse`，不直接把 SQLModel 实体作为公开响应。持久化真题分类由 `exam-category` 边界提供，模拟题动态分类由 `mock` 边界提供，不再用同一请求参数掩盖两种数据源。前端目录 API 应从 `frontend/src/api/subject.ts`、`category.ts` 等统一入口发起，并集中完成 snake_case ↔ camelCase 映射；页面不自行创建 Axios 实例。

### 4.6 错误、并发和兼容策略

- 422：字段类型、长度、范围或请求结构错误。
- 401/403：缺少凭证、凭证失效、非管理员。
- 404：科目、章节、分类或父节点不存在。
- 409：唯一性、跨科目父节点、循环层级、引用或子级冲突；分类写锁竞争（SQLite BUSY/LOCKED）同样返回 409 并提示刷新后重试。
- 5xx：数据库连接、事务锁、树统计基础设施失败；不返回 SQL、堆栈或文件路径。
- 列表/树查询可在客户端使用 AbortController 或“只接受最新响应”规则避免快速切换科目造成旧树覆盖新树；目录写操作不自动重试。
- 当前目录接口已经统一为 POST + Request Schema 和 `ApiResponse`；目录树、科目和分类等小集合使用 `ApiResponse[List[T]]`，没有强制分页。第 4 节目标路径仅用于未来接口命名，若采用必须同步路由、前端 API 入口和验证记录。
