# 账户与权限模块开发设计

> 本文档针对 408考研真题知识点阅读网站中的账户与权限模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。

---

## 1. 需求

### 1.1 模块目标

账户与权限模块解决“系统如何识别当前使用者，以及哪些操作可以执行”的问题。它为学习者提供注册和登录能力，为管理员题库维护、目录维护、统计管理和图片治理提供服务端权限边界。

**已确认事实**：当前项目使用用户名/密码登录；密码通过 `pwdlib[argon2]` 哈希；登录成功返回 JWT、用户名和角色；Token 使用用户 ID 作为 `sub`，受保护请求再从数据库读取账户并检查启用状态和角色。当前运行数据库只保留一个 `admin` 管理员账号。

**设计假设**：本设计继续使用项目已有的 Bearer JWT 作为访问凭证，不引入 OAuth/OIDC、第三方身份服务或服务端 Session 表。

### 1.2 功能需求

| 编号 | 需求 | 可观察行为 |
|---|---|---|
| AUTH-01 | 用户注册 | 提交用户名、密码和可选邮箱；合法且未占用时创建普通用户，重复用户名得到冲突提示。 |
| AUTH-02 | 用户登录 | 用户名和密码正确且账户启用时返回访问凭证、用户名和角色；凭证错误或账户禁用时不能登录。 |
| AUTH-03 | 当前身份识别 | 受保护操作能够得到当前用户 ID、用户名和角色；不存在、失效或对应账户已禁用的凭证不能继续使用。 |
| AUTH-04 | 管理员授权 | 只有角色为 `ADMIN` 的当前用户可以执行题目、科目、分类、统计管理和图片治理操作。 |
| AUTH-05 | 前端身份体验 | 登录后显示用户名和管理员菜单；退出登录后清理浏览器中的凭证与用户信息并回到学习入口。 |
| AUTH-06 | 认证错误区分 | 登录凭证错误、凭证过期、未登录和无管理员权限分别表现为可理解的错误，不混淆 401 与 403。 |

### 1.3 非功能需求

- **安全**：密码不得以明文进入数据库、响应或日志；Token、Cookie 和密钥不得进入日志；管理员判断必须在服务端完成，前端路由守卫只负责导航体验。
- **可靠性**：账户唯一性由数据库唯一约束兜底，应用层预检查只用于提供友好提示；并发注册时不能产生两个相同用户名。
- **可用性**：注册和登录表单需要处理空值、长度、邮箱格式、重复提交、网络失败和后端业务错误；登录失败不能误清除一个仍可用于重试的旧凭证。
- **可观测性**：记录注册成功/冲突、登录成功/失败和受保护操作拒绝等关键事件，记录用户名或账户 ID 等非敏感关联信息，不记录密码和完整 Token。
- **隐私**：认证响应只返回当前页面需要的用户名和角色；邮箱仅作为账户属性保存，不在当前登录响应中返回。

### 1.4 范围与职责边界

- **当前负责**：注册、登录、访问凭证签发、凭证解析、账户启用状态检查和管理员依赖。
- **明确不负责**：密码找回、邮箱验证、刷新 Token、服务端注销黑名单、用户自助修改密码、用户管理后台、细粒度资源所有权和学习进度。
- **协作边界**：题库与目录模块负责业务数据校验；本模块只回答“身份是谁、是否为管理员”。前端 `auth` Store 负责会话展示和本地清理，不得替代后端授权。

### 1.5 验收标准

1. 合法注册后数据库新增一条 `USER` 且密码字段不可还原为明文；重复用户名返回 409 语义的统一错误。
2. 正确凭证登录返回非空 Token、原用户名和角色；错误密码、未知用户名及禁用账户均返回 401 语义且不泄露具体账户存在性。
3. 无 Token 访问管理 API 返回 401，普通用户访问管理 API 返回 403，管理员可以继续执行操作。
4. Token 中的角色被篡改或账户状态变化时，服务端以当前数据库账户为准，不能绕过管理员检查。
5. 前端登录、退出和过期处理不会循环重定向；登录接口自身的 401 不会被当作已登录状态过期而误清除凭证。
6. 密码、Token 和 JWT 密钥在响应、日志和错误消息中均不可见。

## 2. 该项目的模块结构与流程

### 2.1 项目级关系

| 关系 | 当前项目模块 | 协作内容 |
|---|---|---|
| 上游 | 前端登录/注册页面、浏览器输入 | 提供用户名、密码和邮箱等认证输入。 |
| 本模块入口 | `backend-fastapi/app/modules/auth/router.py`、`backend-fastapi/app/modules/auth/dependencies.py` | 分别处理注册/登录和受保护请求的当前用户、管理员依赖。 |
| 业务处理 | `backend-fastapi/app/modules/auth/service.py`、`backend-fastapi/app/core/security.py` | 负责账户查询、密码哈希校验、Token 签发和业务异常。 |
| 数据访问 | `backend-fastapi/app/database/connection.py`、`backend-fastapi/app/modules/auth/repository.py`、`backend-fastapi/app/modules/auth/models.py` | 通过异步 SQLModel Session 和 `UserRepository` 读写 `user` 表。 |
| 下游 | 题库内容、学科目录、统计导出、图片资源治理 | 使用当前管理员身份作为服务端授权条件。 |
| 前端协作 | `frontend/src/api/auth.ts`、`frontend/src/stores/auth.ts`、`frontend/src/router/index.ts` | 发起认证请求、持久化会话展示信息、执行登录体验守卫。 |

### 2.2 当前代码边界与事实冲突

当前处于后端结构迁移过渡期：认证模块已按业务域归入 `backend-fastapi/app/modules/auth/`，题库核心、统计导出和媒体能力也已归入对应业务模块；数据库连接、全局异常和安全算法仍由共享基础设施提供。当前没有独立的 Session/Token 表，模型由 `main.py` 显式加载各业务模块模型；历史遗留表不再建立 ORM 映射。

- `AuthService.register()` 只执行账户重复检查和新增，写入由 Service 显式提交，异常由 `get_async_session` 回滚。
- `AuthService.login()` 查询用户、校验密码和启用状态后调用安全工具签发 JWT。
- `get_current_user()` 从 Bearer Token 读取用户 ID，再查询数据库；`get_current_admin()` 在此基础上检查 `ADMIN`。
- 前端 `request.ts` 自动附加 Bearer Token，并在非登录接口遇到 401 时清理 Token、跳转登录页。
- `router/index.ts` 的 `requiresAuth`/`requiresAdmin` 只保护页面导航，不是服务端权限边界。

认证接口已按项目规范使用 POST、Request Schema 和 `ApiResponse`；当前成功码继续保持 `200` 以兼容前端。后续新增认证接口必须沿用 POST-only 规则。

### 2.3 核心流程

```mermaid
flowchart LR
    U[用户填写认证信息] --> V[Request Schema 校验]
    V --> Q[查询账户]
    Q --> P[密码与状态校验]
    P --> T[签发访问凭证]
    T --> S[浏览器保存会话]
    S --> A[服务端重新确认身份]
    A --> G[执行受保护业务]
```

### 2.4 数据流与状态流

1. 注册表单在浏览器中保留未提交的密码，提交时只发送到认证接口；后端哈希后写入 `user.password`。
2. 登录成功后，Token 写入 `web408_token`，用户名和角色写入 `userInfo`；后端不保存访问 Token。
3. 受保护请求携带 Bearer Token；服务端解码后按 `sub` 中的用户 ID 查询 `user`，并以数据库中的 `enabled` 和 `role` 为最终状态。
4. 退出登录只删除浏览器本地 Token 与用户信息，不产生服务端撤销记录；当前项目没有 Refresh Token 或注销黑名单。
5. 账户删除、角色变更和密码修改当前没有公开操作闭环；数据库中的账户数据按当前模型长期保留。

### 2.5 异常、并发、事务和日志规则

- **输入异常**：Pydantic `RegisterRequest` 约束用户名 3～50 字符、密码 6～20 字符和可选邮箱格式；结构错误由全局校验处理器映射为 422。
- **业务异常**：重复用户名映射为 409；用户名/密码错误、Token 无效或账户禁用映射为 401；普通用户访问管理操作映射为 403。
- **并发注册**：应用层先查重，数据库 `username` 唯一索引最终兜底；若竞争导致唯一约束异常，应在 API 边界映射为 409，而不是 500。
- **事务**：当前实际事务所有者是认证写用例，`AuthService.register` 在用户写入成功后显式提交；请求会话在异常时回滚并关闭。实现新写用例时保持一个请求一个事务，不让 Repository 或辅助函数自行提交。
- **重试**：登录读取和 Token 签发可以由用户手动重试；注册不是可静默自动重试的非幂等操作，客户端不得无条件自动重放。
- **日志**：使用现有 `configure_logging` 配置根日志器，业务模块通过标准库命名日志器记录认证里程碑和失败原因；禁止记录密码、Token、JWT 载荷和完整邮箱。当前日志包含用户名，后续应避免把用户名作为高敏感数据扩散到公共日志。
- **异常处理**：统一处理器对外返回固定公开消息，内部异常仅写受控日志；数据库唯一约束冲突映射为 409。

### 2.6 关键技术选择

- 保留 `pwdlib` 推荐的 Argon2 哈希，避免在模块内新增密码算法。
- 保留 JWT Bearer 形态以兼容现有前端；Token 使用稳定的用户 ID 作为 `sub`，不设置 `exp`，不会自动过期。Token 仍可通过禁用账户、修改密钥等方式使其失效。
- 密钥从环境配置或密钥管理系统读取，算法限制为 `HS256`，不依赖代码中的默认密钥。

## 3. 数据库的设计

### 3.1 数据库与连接方式

- **数据库**：SQLite，连接 URL 当前默认为 `sqlite+aiosqlite:///./data/web408.db`。
- **访问方式**：SQLModel + `AsyncSession`；FastAPI 通过 `SessionDep` 注入，每个请求创建并关闭一个 Session。
- **Schema 来源**：`SQLModel.metadata.create_all` 在应用生命周期启动时执行；历史高优先级结构修复仅保留 `schema_migrations` 记录，当前没有迁移脚本或完整通用迁移框架，也没有独立用户 Session 表。
- **当前连接事实**：`connection.py` 为 SQLite 连接启用了 `check_same_thread=False`、WAL、外键约束和忙等待；现有数据通过 `001_high_priority_security_and_integrity` 迁移保留。
- **设计建议**：后续核验外键删除语义、锁冲突处理和认证数据备份；本文档未执行数据库操作。

### 3.2 `user` 实体

| 字段 | SQLModel/Python 类型 | 可空/默认 | 约束与用途 |
|---|---|---|---|
| `id` | `int` | 数据库生成 | `PRIMARY KEY`，继承 `BaseModel`。 |
| `create_time` | `datetime` | 非空；当前 UTC 工厂默认 | 账户创建时间。 |
| `update_time` | `datetime` | 非空；当前 UTC 工厂默认并配置 on update | 账户最后更新时间。 |
| `username` | `str` | 非空 | `UNIQUE`、索引；登录查找和注册唯一性边界。 |
| `password` | `str` | 非空 | 保存 Argon2 哈希，不返回给客户端。 |
| `email` | `Optional[str]` | 可空 | 可选联系信息；当前没有验证/找回闭环。 |
| `role` | `str` | 非空；默认 `USER` | 角色值当前为 `ADMIN`/`USER`/`GUEST`。 |
| `enabled` | `bool` | 非空；默认 `True` | 账户是否允许登录和访问受保护业务。 |

### 3.3 关系、索引和约束

- `ExamQuestion.author_id`、`MockQuestion.author_id` 引用 `user.id`；账户模块只维护被引用的身份，不负责题库业务数据。
- `username` 保持唯一索引；数据库迁移已增加用户角色检查约束，管理员角色仍由服务端数据库状态确认。
- 登录按 `username` 精确查询，现有唯一索引足够；在没有用户后台列表、按角色筛选等真实查询前，不新增无依据的复合索引。
- 当前没有用户删除 API。若未来开放删除，必须先处理作者外键、审计要求和隐私删除范围，不能直接依赖级联删除题库内容。

### 3.4 生命周期、隐私和备份边界

- 新用户从 `USER + enabled=true` 开始；当前没有禁用/删除管理闭环，状态主要由已有数据或外部数据库操作改变。
- 密码哈希随账户保存，Token 只存在浏览器；退出登录不会改变数据库。
- SQLite 数据库属于本地运行数据；备份应保护整个数据库文件权限，导出用户数据时脱敏密码哈希和认证字段。
- 当前不执行删除或重建。数据库保留历史 `schema_migrations` 记录；后续模型变化按当前模型处理，删除或重建开发数据库必须先获得明确授权。

### 3.5 事务与一致性

注册是本模块唯一当前写事务：检查用户名、创建 User 和 `AuthService` 显式提交必须属于同一事务；唯一约束失败回滚。登录和 Token 解析是只读事务，不写认证状态。多个并发请求不能共享同一个 `AsyncSession`。

## 4. API 接口的设计

### 4.1 当前已实现边界（事实）

- 公共前缀实际为 `/api`；认证路由位于 `backend-fastapi/app/modules/auth/router.py`，当前应用没有公开 `/api/v1` 前缀。
- 当前用户和管理员依赖位于 `backend-fastapi/app/modules/auth/dependencies.py`；请求级数据库会话依赖仍位于 `backend-fastapi/app/api/dependencies.py`。
- 已实现 `POST /api/auth/register` 和 `POST /api/auth/login`，两者均接收 Pydantic JSON Request Schema。
- 成功响应实际使用 `{code: 200, message, data}`；注册 `data=null`，登录 `data` 为 Token、用户名和角色。
- 前端 `frontend/src/api/auth.ts` 通过统一 Axios 实例调用；`frontend/src/views/user/Login.vue` 和 `Register.vue` 负责表单及页面反馈。

### 4.2 目标契约与方法规则

本模块 Web API 使用 POST、Request Schema 和 `ApiResponse[T]`；列表响应使用 `lists` 和 `pagination`。现有成功码继续保持 `200`，以兼容前端请求层。

| 接口名称 | 目标路径与方法 | Request Schema / 输入 | 成功结果 | 鉴权与资源边界 |
|---|---|---|---|---|
| 用户注册 | `POST /api/auth/register` | `RegisterRequest`：`username` 3～50 字符、`password` 6～20 字符、可选 `email`。 | `ApiResponse[None]`，消息为注册成功。 | 公开；服务端强制角色为 `USER`，忽略客户端角色字段。 |
| 用户登录 | `POST /api/auth/login` | `LoginRequest`：`username`、`password`。 | `ApiResponse[AuthResponse]`；`AuthResponse` 仅含 `token`、`username`、`role`。 | 公开；只对启用账户签发凭证。 |

### 4.3 校验、错误和状态表达

| 场景 | HTTP 语义 | 公开业务消息 |
|---|---:|---|
| JSON 字段缺失、长度或邮箱格式错误 | 422 | 由统一校验处理器返回字段定位信息。 |
| 用户名已存在 | 409 | “用户名已存在”，不返回数据库细节。 |
| 用户名或密码错误 | 401 | 统一使用“用户名或密码错误”，避免枚举账户。 |
| 账户已禁用 | 401 | “账户已被禁用”。是否对外区分该消息需按威胁模型确认；推荐登录阶段使用统一失败消息。 |
| Token 缺失、签名错误或过期 | 401 | “未提供认证令牌”或“无效的认证令牌”。 |
| 普通用户访问管理员依赖 | 403 | “需要管理员权限”。 |
| 数据库/哈希/签发失败 | 5xx | 固定“服务器内部错误”；详细异常只进受控日志。 |

### 4.4 幂等、会话与前端调用

- 注册以 `username` 唯一约束为幂等冲突边界：同一请求重复提交不创建第二个账户，返回 409；客户端只允许用户主动重试。
- 登录是无副作用的读取加 Token 签发，可手动重试，但每次成功可能产生新 Token；当前没有刷新或撤销机制。
- `request.ts` 统一注入 Bearer Token、处理 HTTP 错误和业务码；页面不得自行创建 Axios 实例或重复拼接认证头。
- 前端 `auth.ts` Store 保存 Token 和用户展示信息；路由守卫用于体验，后端 `get_current_admin` 才是安全边界。
- 认证 API 不提供分页、排序、取消、流式任务或后台任务。

### 4.5 认证配置与兼容要求

- 当前配置项为 JWT secret、algorithm；目标实现必须固定允许算法并从环境配置读取生产密钥。
- Token 当前使用 60 分钟短生命周期；项目暂未引入 Refresh Token。
- 前端继续识别 `code===200`，请求模块与后端 `ApiResponse` 契约保持一致。
