# 公式排版规范

版本：1.0。适用对象：408web 题库图片转 JSON 录入助手。配套文件：《分类标签清单.md》（上传名也可为《分类标签清单(1).md》）。

本文件是公式格式规范，不是知识点目录、答案库或新的 JSON 字段定义。示例只说明写法；示例中的数值、符号、答案字母、题型及图形不能替代当前题目的内容。除明确标为“JSON 源码”的内容外，公式示例均按 **JSON 解析后的 Markdown 内容**书写。

## 统一风格与适用范围

### 固定默认风格

采用朴素、统一的数学排版：行内公式用 `$...$`，独立公式用 `$$`；常规分式统一用 `\frac`；变量与运算关系使用标准 LaTeX；单位和多字母缩写使用正体。独立公式的起止 `$$` 各占一行，公式块与相邻内容之间空一行。

不能因为题目不同而随意改用 `\(...\)`、`\[...\]`、代码式公式、Unicode 上下标或 HTML 上下标。不能为突出结果临时改用框线、颜色、大字号、加粗数学字体或手工对齐。这里的统一仅限排版，不改变原题条件、数学含义和代码语法。

### 适用字段

统一检查 `content`、`options.A` 至 `options.D`、非空 `answer` 中的数学表达；`title` 原本含数学表达时也适用，但不得为添加公式而生成或改写标题。选项顺序、选项数值和题目小问必须保持原样。

`category` 必须使用分类清单中的原名，不能为了排版添加美元符号或修改空格、大小写。`source`、年份、题号、科目 ID、难度等元信息不做数学化处理。`answer` 为 `null` 时保留 `null`，不为满足格式要求编造答案。

### 先区分数学表达与字面内容

公式中的 `a/b`、`x<=y`、`n^2` 可以在含义明确时规范成分式、不等式和幂。但程序代码、汇编、文件名、路径、URL、协议报文、正则表达式、原始字符串和 SVG 属性必须保持各自语法，不能执行全局替换。

数学变量用 `$n$`、`$i$`；正文中的 CPU、TCP、Cache 等术语直接写普通文本，不把每个英文词或普通数字都包成公式。正文引用程序标识符时可写 `next[i]`；在数学推导中引用同一数组元素时可写 `$\mathrm{next}[i]$`，二者不能混为一类。

格式规范允许统一等价的排版写法，不允许补上看不清的指数、改变负号或不等号、补定对数底数、修改精度、删去前导零或替换题目中的单位。内容歧义按主提示词处理，不靠排版猜测。

### 规范执行方式

每题先读取通用规则，再按本题出现的分式、取整、单位、位串、矩阵等读取对应条目，最后核验 JSON 两层表示。当前上下文已有完整有效原文时可直接核验；文件更新后重新读取。

未列出的数学形式，优先用本文件已列出的基础命令组合表达；确需其他语义性命令时，仅使用不依赖自定义宏或外部资源的常规 LaTeX，保持同一版式。不因清单未穷举而改回纯文本公式，也不使用未经依据的公式替代原式。

本文件只约束数学排版与相关序列化，不改变主提示词的分类、求解、SVG 触发条件或最终 JSON 契约。文件中的代码块是展示规范的载体，不要求在最终题库字段中把公式放进代码块。

## 定界符与段落布局

### 行内公式

变量、下标、复杂度、条件、选项中的数学内容，以及能够自然嵌入句子的简短关系使用单个美元符号。定界符内侧不留无意义的首尾空格，不换行。

```markdown
设结点数为 $n$，则边数为 $n-1$。

当 $i\leq j$ 时，比较 $a_{i}$ 与 $a_{j}$。

该算法的时间复杂度为 $O(n\log_{2} n)$。
```

一句话中的完整关系尽量放在同一对定界符中：使用 `$a+b=c$`，不要拆成 `$a$+$b$=$c$`。一句话中的不同独立量仍可分别写成 `$a$`、`$b$`，不为了合并而将整段中文放入公式。

选择题选项默认只用行内公式，即使选项全部由一个公式组成，也不另起块级公式。选项确实包含多行矩阵或分段式时，以保留原式结构为先，按后文的复杂公式规则处理，不强行压成一行。

### 独立公式

需要单独强调的关键关系、较长的代入计算、核心推导和重要结果使用块级公式。不是所有等式、数值和计算结果都必须单独成块；短结果可直接嵌入结论，避免页面被过多公式块割裂。

统一写法如下，`$$` 各占一行，公式块前后各空一行：

```markdown
传输时间由数据量与传输速率确定：

$$
T=\frac{L}{R}
$$

其中，$L$ 表示数据量，$R$ 表示传输速率。
```

最终数学内容中不使用 `\(...\)`、`\[...\]` 或 `equation`、`displaymath` 环境充当另一套定界方式。块内不再嵌套 `$...$` 或另一组 `$$`，`$$` 之间不插入空段。

### 多步计算

较短的连续计算可以在同一块中用等号连接；过长时按实际推导阶段拆成多个公式块，必要的解释置于块外。每块表达一个可读的阶段，不在普通公式中靠回车、连续空格或 `\\` 强行分行。

```markdown
先写出关系：

$$
T=\frac{L}{R}
$$

代入本例的 $L=8000\,\mathrm{bit}$ 与 $R=10^{6}\,\mathrm{bit/s}$：

$$
T=\frac{8000}{10^{6}}\,\mathrm{s}=8\,\mathrm{ms}
$$
```

普通逐步计算不使用 `aligned`、`align`、`gathered`、`eqnarray` 等环境仅作视觉对齐，不把整道题全部推导塞进一个大公式。矩阵、分段函数等本身需要结构的数学对象按“必要的复杂公式”处理，不适用这一排除。

### 中文、强调与标点

解释、条件说明和结论以普通中文放在公式外，数学关系放在公式内。中文句末标点一般放在行内定界符外；独立公式一般不附中文句号。公式中的必要集合分隔符、函数参数逗号等仍保留。

只有语义必需的短中文下标或分段条件才使用 `\text{...}`，例如 `$[x]_{\text{补}}$`。不把一整段中文、选项辨析或解题步骤塞进 `\text{...}`。

正确答案首行仍按主提示词整行加粗，例如 `**正确答案：C**`。不要把公式包在 Markdown 加粗中，不写 `**$...$**` 或 `**$$...$$**`；也不默认使用 `\boxed`、`\color`、`\mathbf`、`\boldsymbol`、`\displaystyle`、`\dfrac`、`\tfrac`、`\Huge` 或字号缩放制造另一种视觉风格。原题若用粗体区分向量等数学对象，应保留这种语义差别，不能当作装饰一律删除。

### 表格、列表与代码块

Markdown 表格内只用短行内公式，较长推导放表外；单元格不使用 `$$`、多行计算环境或人为换行标签。原题表格确含复杂对象时优先在表外保留该对象并明确对应关系，不压缩、删改数学内容。

公式中的绝对值、集合基数和条件竖线使用 `\lvert`、`\rvert`、`\mid`，不直接把数学竖线写成表格分列符。

```markdown
| 项目 | 表达式 |
|---|---|
| 元素个数 | $\lvert S \rvert$ |
| 时间复杂度 | $O(n^{2})$ |
```

原题小问编号按主提示词保留。需要展示较长公式时，优先放在对应小问的普通段落之后；不要为了对齐列表加入大量空格、制表符或不必要的深层嵌套。确需位于列表项内时，保持合法的 Markdown 缩进，不使公式意外成为代码块。

正文公式不放反引号、`latex`、`math`、`text` 等代码块。程序代码仍放相应语言的代码块，SVG 仍按主提示词放 `svg` 代码块；不得为统一公式而删除这些代码围栏。

## 数学符号写法清单

本节表格中的写法均是 **Markdown 层**，不是 JSON 字符串。反引号只是用于展示源码，不能随公式复制到最终字段中。数学对象的语义优先于外观统一，不对程序运算符或原始数据应用本表替换。

### 变量、上下标与函数

| 场景 | 统一写法 | 约束 |
|---|---|---|
| 单字母变量 | `$n$`、`$x$`、`$T$` | 保留原题大小写和指代。 |
| 数学下标 | `$a_{i}$`、`$a_{i+1}$` | 下标统一用花括号分组；不写 `a\_i`。 |
| 幂与指数 | `$n^{2}$`、`$2^{m+n}$`、`$10^{-6}$` | 指数统一用花括号；不使用 Unicode 上标代替公式。 |
| 多字母缩写 | `$\mathrm{CPI}$`、`$\mathrm{RTT}$` | 按一个缩写处理，不排成多个变量相乘。 |
| 说明性英文下标 | `$T_{\mathrm{avg}}$`、`$T_{\mathrm{CPU}}$` | 英文标记用正体，数学索引仍按变量排版。 |
| 普通函数 | `$f(x)$`、`$T(n)$` | 同一函数全题保持一致。 |
| 对数 | `$\log_{2} n$`、`$\ln n$` | 使用函数命令；只保留题目或推导已确定的底数。 |
| 最大值与最小值 | `$\max(a,b)$`、`$\min(a,b)$` | 不把 max、min 当成变量串。 |
| 三角函数 | `$\sin x$`、`$\cos x$` | 仅在原题确有该对象时使用，不补充无关公式。 |

### 运算、分式与取整

| 场景 | 统一写法 | 约束 |
|---|---|---|
| 加减 | `$a+b$`、`$a-b$` | 不用全角运算符或长破折号替代减号。 |
| 显式数量相乘 | `$a\times b$`、`$64\times 8$` | 数值计算统一用 `\times`，不用字母 x 或程序星号。 |
| 既有数学乘积 | `$ab$`、`$a\cdot b$` | 原式的省略乘号、内积等含义需保留，不能全局替换。 |
| 分数与除法计算 | `$\frac{a}{b}$`、`$\frac{a+b}{c}$` | 分子、分母均用花括号；普通分式不混用 `\dfrac`、`\tfrac`。 |
| 根式 | `$\sqrt{x}$`、`$\sqrt[k]{x}$` | 不以 `sqrt(x)` 程序形式代替公式。 |
| 向下取整 | `$\lfloor x\rfloor$` | 只在确为向下取整时使用。 |
| 向上取整 | `$\lceil x\rceil$` | 不与四舍五入、截断混淆。 |
| 绝对值或基数 | `$\lvert x\rvert$`、`$\lvert S\rvert$` | 在表格内外保持同一写法。 |
| 取模关系 | `$r=a\bmod m$` | 代码中的 `%` 保持原样；不把百分号当取模。 |
| 百分数 | `$50\%$` | 公式内转义百分号；普通正文中的 `%` 无需改成数学命令。 |
| 科学计数法 | `$1.6\times 10^{-6}$` | 只调整数学排版，不改有效数字或代码中的 `1.6e-6`。 |

同一个表达式的分母范围必须准确。例如 `$\frac{a}{b+c}$` 与 `$\frac{a}{b}+c$` 含义不同，不能凭外观选择。原题以除号本身为考查内容时保留其必要表示，不机械替换。

### 关系、集合与常用数学结构

| 场景 | 统一写法 | 约束 |
|---|---|---|
| 不等关系 | `$a\leq b$`、`$a\geq b$`、`$a\neq b$` | 数学中不混用 `<=`、`>=`、`!=`；程序代码除外。 |
| 近似关系 | `$x\approx 0.33$` | 仅在确为近似时使用，不把精确等号随意改成近似号。 |
| 集合 | `$\{0,1,2\}$` | 显示集合花括号时使用转义花括号。 |
| 集合条件 | `$\{x\mid x>0\}$` | 条件竖线使用 `\mid`。 |
| 属于关系 | `$x\in S$`、`$x\notin S$` | 保留原题逻辑方向。 |
| 并集与交集 | `$A\cup B$`、`$A\cap B$` | 不替换为普通字母。 |
| 空集 | `$\varnothing$` | 不用数字 0 或空字符串代替。 |
| 求和 | `$\sum_{i=1}^{n} a_{i}$` | 上下限分组，不为改外观附加 `\limits`。 |
| 连乘 | `$\prod_{i=1}^{n} a_{i}$` | 必须与原题运算一致。 |
| 极限 | `$\lim_{n\to\infty} f(n)$` | 变量、趋近方向与目标保持原义。 |
| 希腊字母 | `$\alpha$`、`$\beta$`、`$\lambda$` | 数学中用命令；原始文本、代码和图内文字不全局替换。 |
| 逻辑非与异或 | `$\overline{x}$`、`$x\oplus y$` | 不改写为逻辑意义不同的运算符。 |

普通括号直接使用 `(`、`)` 或 `[`、`]`；确需包围较高分式等结构时才配对使用 `\left`、`\right`。不得只使用其中一侧，或为普通的 `$f(x)$` 无意义地加大括号。文本行进顺序和图的箭头仍由主提示词决定，本表不改变图示要求。

### 单位、空格与数值

纯正文可写“存取时间为 40 ns”；进入完整数学式时写 `$T=40\,\mathrm{ns}$`。同一层级、同类表达保持一致，不把所有独立数值强制转成公式。

| 场景 | 统一写法 | 约束 |
|---|---|---|
| 时间 | `$40\,\mathrm{ns}$`、`$8\,\mathrm{ms}$` | 数值与单位之间用 `\,`。 |
| 微秒 | `$5\,\mu\mathrm{s}$` | 在公式中统一希腊字母与单位写法。 |
| 频率 | `$2.5\,\mathrm{GHz}$` | 单位大小写不变。 |
| 位数 | `$32\,\mathrm{bit}$` | 不与字节单位 B 互换。 |
| 字节容量 | `$4\,\mathrm{KB}$`、`$4\,\mathrm{KiB}$` | 保留原题单位及换算依据，不擅自互换。 |
| 传输速率 | `$100\,\mathrm{Mbit/s}$` | 单位中的 `/` 可保留，不强改成分式。 |
| 结果单位 | `$T=8\,\mathrm{ms}$` | 计算结论不能漏掉必要单位。 |

不要只为排版统一而把 KB 改成 KiB、把 Mbps 改成 MB/s、把十进制换算改为二进制换算，或修改有效数字与舍入方式。题目记号可能有约定；换算必须根据当前题意独立判断，格式文件不提供默认答案。

LaTeX 命令与后续字母之间保留必要空格，例如 `\log n`，不连写成另一个命令。不要用全角空格、制表符、连续空格、`\hspace`、`\vspace`、`\quad`、`\qquad` 等手工凑对齐；单位间距 `\,` 和数学语法必需的空格不在此限。

## 408 学科记号与边界

本节只规定表示方式，不规定知识点归属、解题方法或变量取值。同一量在一道题的题干、选项、公式、表格和图中应保持可对应；规范只能做含义不变的排版转换，不随意重命名原题变量。

### 数据结构

复杂度使用 `$O(n)$`、`$O(n\log_{2} n)$`、`$O(n^{2})$`、`$\Theta(n)$`、`$\Omega(n)$` 等；保留原题使用的复杂度记号，不把 O、Θ、Ω 当作外观等价项互换。对数底数不明时保持原式，不为满足示例写法强行补成 2。

数学序列下标写 `$a_{i}$`；程序数组访问写 `a[i]`，结构体成员、指针表达式和递归代码保持原样。在公式中按一个程序标识符引用数组元素时可写 `$\mathrm{next}[i]$`、`$\mathrm{nextval}[i]$`，不得将变量名中的字母逐个解释为乘积。

图的顶点集合与边集合可写 `$V$`、`$E$`，基数写 `$\lvert V\rvert$`、`$\lvert E\rvert$`；已经使用 `$n$`、`$m$` 的题目不强行换名。集合、遍历序列、栈内容和代码字符串要先按题意区分，不能为了整齐改变顺序或加删括号。

### 操作系统

数学中的页号、块号、时间等仍用原题变量；英文说明性下标可写 `$T_{\mathrm{avg}}$`，数学索引用 `$T_{i}$`。进程名称若是标识 P0、P1，需先核对原题是否表达下标，再决定写作 `$P_{0}$`、`$P_{1}$`；不要对原始日志、程序或地址作这种替换。

分页、文件分配、调度等计算中的向上取整、向下取整、平均值和近似值，按实际求解含义使用对应命令。不能因为数值看起来相近而把取整符号替换成括号，或把最终舍入结果连接到精确等号后。

### 计算机网络

公式中的 TCP 性能量或缩写按一个整体处理，例如 `$\mathrm{RTT}$`；正文中的 TCP、UDP、IP 直接用普通文本。公式中的速率、时延、长度、比率保留题目原单位和定义，不根据字母名称猜测量纲。

IPv4 地址、IPv6 地址、CIDR、子网掩码、MAC 地址、URL、协议字段和报文位串优先按原始文本或代码保留。例如 `192.168.1.0/24` 中的斜杠不是分式，不能改写为 `\frac`，也不能把地址小数点当作乘号。

### 计算机组成原理

多字母寄存器名、性能指标或部件缩写在公式中用正体，例如 `$\mathrm{PC}$`、`$\mathrm{MAR}$`、`$\mathrm{MDR}$`、`$\mathrm{IR}$`、`$\mathrm{CPI}$`；正文或程序中的名称保持普通文本或代码形式。

进制的数学下标表示可写 `$(101101)_{2}$`、`$(3FA0)_{16}$`；原题明确使用 `0x3FA0`、`3FA0H` 等字面形式时保持原表示，不擅自转成另一种题目数据。必须保留前导零、位宽、分隔关系和正负号。

原码、反码、补码的短中文下标可写 `$[x]_{\text{原}}$`、`$[x]_{\text{反}}$`、`$[x]_{\text{补}}$`。位串本身可保留为 `00101101`；需要放在数学运算中时可用 `$\mathtt{00101101}$`，不得按十进制整数去掉前导零。

逻辑非、补码符号、位运算和普通算术含义不同。C/C++ 中的 `~`、`^`、`&`、`|`、`<<`、`>>` 必须保留代码语法，不自动映射成幂、指数或普通乘除。

### 必要的复杂公式

真正需要保持矩阵、分段函数等二维数学结构时，允许使用 `bmatrix`、`pmatrix`、`cases` 等语义明确的常规环境。优先放在一个独立公式块中；选项含这类结构时保留必要结构，不拆成与原式无法对应的散句。

```markdown
$$
A=\begin{bmatrix}
1 & 0 \\
0 & 1
\end{bmatrix}
$$
```

这些环境内用于分列的 `&` 和用于分行的 `\\` 是结构语法，必须保留；不能把它们当作普通公式中的多余字符删除。复杂数学对象与 Markdown 表格、地址格式图、程序框图不是同一回事，不用 `array` 或矩阵环境代替普通文字表格或 SVG 图示。

不依赖 `\newcommand`、`\def`、外部宏包、外部字体、HTML、MathML、脚本或自定义渲染扩展。不为了排版生成图片版公式；题图中的复杂公式可以在图外以 LaTeX 表达，但不得改变主提示词要求保留的图形关系。

SVG 中的标签按 SVG 规则使用普通文字或必要 Unicode，不把 `$...$`、`$$...$$` 或 LaTeX 命令直接写进 `<text>` 并假设它会自动渲染。复杂公式放图外，数学含义与图内标签保持一致。

## Markdown 与 JSON 两层表示

### 先写内容，再序列化一次

先形成正常的 Markdown 字段值，再对整个对象执行一次标准 JSON 序列化。最终交付的是 JSON 源码；导入后解析出的字段值才是 Markdown。两层不能混写，不能先把字段手动 JSON 转义后再交给序列化函数。

以下对照中的反引号是文档展示标记，不属于实际内容：

| 意图 | Markdown 字段中的实际内容 | JSON 字符串源码中的写法 |
|---|---|---|
| 行内分式 | `$\frac{a}{b}$` | `"$\\frac{a}{b}$"` |
| 数学下标 | `$a_{i}$` | `"$a_{i}$"` |
| 集合 | `$\{0,1\}$` | `"$\\{0,1\\}$"` |
| 百分数 | `$50\%$` | `"$50\\%$"` |
| 加粗 | `**答案**` | `"**答案**"` |
| 一个英文双引号 | `"` | `"\""` |

上表中每一格的外层英文双引号仅在 JSON 栏表示 JSON 字符串本身的边界。例如 Markdown 中 `$\frac{a}{b}$` 的反斜杠有一个，最终 JSON 字符串内的 `\\frac` 有两个。

### 换行与反斜杠

Markdown 中的实际换行在 JSON 字符串源码里写成 `\n`，一个空行通常写成 `\n\n`。JSON 解析后必须还原为真正的换行，不能在网页正文里显示字面 `\n`。

Markdown 中一个实际反斜杠在 JSON 中写成两个。一个数学环境的换行命令 `\\` 在 Markdown 中本来就有两个实际反斜杠，因此 JSON 中必须写成四个。这不属于重复转义，而是正确保存两字符的语法。

必须特别检查 `\frac`、`\rfloor`、`\rceil`、`\nabla`、`\neq`、`\times`、`\text`、`\bmod`、`\begin` 等命令，避免 `\f`、`\r`、`\n`、`\t`、`\b` 被 JSON 解析成意外控制字符。不能仅以“JSON 能解析”判断公式正确，解析成功也可能已损坏命令。

不要把 Markdown 的 `**`、`#`、`$`、数学下标 `_` 或代码围栏的反引号统一加反斜杠。不要写 JSON 不支持的 `\*`、`\$`、`\_` 等转义；也不要把它们多转义一次后当作正确格式输出，导致正文显示多余符号。

代码中的字面反斜杠必须保留。例如 C 代码 `printf("%d\n", result);` 中的 `\n` 是两个字面字符，应按反斜杠序列化；代码行之间的实际换行则按真正换行序列化。二者不能做同一种文本替换。

### 行内公式配对示例

以下两段表示同一个 `answer` 字段内容，只说明语法，不是完整题目对象。

Markdown 字段值：

```markdown
**答案**

设数据量为 $L$，传输速率为 $R$，则传输时间为 $T=\frac{L}{R}$。
```

对应的 JSON 源码：

```json
{
  "answer": "**答案**\n\n设数据量为 $L$，传输速率为 $R$，则传输时间为 $T=\\frac{L}{R}$。"
}
```

### 独立公式与代入配对示例

Markdown 字段值：

```markdown
**答案**

本例中，数据量为 $8000\,\mathrm{bit}$，传输速率为 $10^{6}\,\mathrm{bit/s}$。

$$
T=\frac{L}{R}
$$

代入可得：

$$
T=\frac{8000}{10^{6}}\,\mathrm{s}=8\,\mathrm{ms}
$$
```

对应的 JSON 源码：

```json
{
  "answer": "**答案**\n\n本例中，数据量为 $8000\\,\\mathrm{bit}$，传输速率为 $10^{6}\\,\\mathrm{bit/s}$。\n\n$$\nT=\\frac{L}{R}\n$$\n\n代入可得：\n\n$$\nT=\\frac{8000}{10^{6}}\\,\\mathrm{s}=8\\,\\mathrm{ms}\n$$"
}
```

解析后的 `$$` 必须各占一行，块内公式恢复为单个反斜杠的命令。不能将 `\n` 当作文本拼进 LaTeX 命令，也不能在公式外层再加一组美元符号。

### 选项、表格与复杂结构示例

选择题片段，只演示各个选项独立采用同一种行内公式风格：

```json
{
  "content": "某算法的时间复杂度为（ ）。",
  "options": {
    "A": "$O(n)$",
    "B": "$O(n\\log_{2} n)$",
    "C": "$O(n^{2})$",
    "D": "$O(2^{n})$"
  }
}
```

表格片段，数学竖线不会与表格分列符混淆：

```json
{
  "answer": "**答案**\n\n| 项目 | 数学表达 |\n|---|---|\n| 元素个数 | $\\lvert S \\rvert$ |\n| 平方 | $n^{2}$ |"
}
```

矩阵片段，注意 JSON 源码中的矩阵换行命令有四个实际反斜杠：

```json
{
  "answer": "**答案**\n\n$$\nA=\\begin{bmatrix}1 & 0 \\\\ 0 & 1\\end{bmatrix}\n$$"
}
```

这些片段不包含主提示词要求的全部字段，不能直接作为一道完整题目交付；其中的 `answer` 前缀应按实际题型使用，不能照抄为固定答案。

### 代码和 SVG 同时存在的示例

程序片段中的运算符、字符串转义和代码围栏保持原样；数学表达只修改代码块外的部分：

```json
{
  "answer": "**答案**\n\n程序代码保持原样：\n\n```c\nresult = a / b;\nif (x <= y) {\n    printf(\"%d\\n\", result);\n}\n```\n\n数学商单独写为 $\\frac{a}{b}$，不要把代码中的除法符号改成 LaTeX。"
}
```

SVG 和 LaTeX 共存时，SVG 根元素仍是实际 `<svg>`，xmlns 仍是属性中的普通地址，不能变成 Markdown 链接，也不能将整个 SVG 转为 `&lt;svg&gt;`：

```json
{
  "answer": "**答案**\n\n示例公式为 $x=\\frac{a}{b}$。\n\n### 图示分析\n\n```svg\n<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 180 60'><line x1='55' y1='30' x2='125' y2='30' stroke='#555' stroke-width='2'/><g font-size='18' fill='#222' text-anchor='middle'><text x='35' y='36'>甲</text><text x='145' y='36'>乙</text></g></svg>\n```\n\n此图仅演示 SVG 与公式同时存在时的嵌入语法，不代表当前题目的结构。"
}
```

SVG 文本节点里的 XML 特殊字符仍按 XML 规则处理，这与将整个 SVG 源码实体化不同。SVG 属性使用单引号时无需额外做 JSON 双引号转义，完整字段仍只序列化一次。

### 交付形式

最终完整对象、字段集合、是否包含 `options`、首行答案格式，以及是否需要 SVG，全部遵循主提示词。本文件不新增 `formula`、`latex`、`mathml`、`formatVersion` 或 `renderedContent` 等字段。

成功时只交付主提示词要求的一个 JSON 代码块；字段中的公式不另外在代码块外渲染，不附相同公式的纯文本版、截图版或 HTML 副本。规范文件中的分层示例不改变这一输出要求。

## 交付前检查与兼容边界

### 内容与排版检查

检查所有适用字段，而非只检查答案。确认题干与选项中的数字、正负号、幂、下标、括号范围、精度、单位、位串和代码均未被误改；同一对象的记号在全题中一致。检查公式没有吞入整段中文，简短公式没有被无必要地拆成多块。

确认只采用规定的行内和独立定界方式，定界符与花括号配对。代码块、字面美元符号和 SVG 源码要先排除在数学范围之外，不能只靠统计全部美元符号是否为偶数判断正确性。必要矩阵或分段式的环境应成对，结构性换行不得丢失。

检查分式统一用 `\frac`，上下标有正确分组，多字母缩写与单位符合规则，表内只有短行内公式，无不必要的彩色、加粗、框线、大字号和手工间距。保留原题具有语义作用的粗体、向量及必要数学结构，不把它们误删为装饰。

### 序列化检查

有代码工具时，以真实对象进行标准序列化，并重新解析；逐字段比较解析结果与序列化前的原始字符串是否完全一致。另检查原始字符串自身的公式语法，防止“错误的原文成功往返”被当作正确。

解析后重点检查反斜杠命令、实际换行、代码中的字面 `\n`、加粗星号、公式定界符和 SVG 标签。不允许公式范围内出现由命令前缀误转义产生的制表、回车、换页或退格等字符；原始代码或题目明确要求的字符另行保留，不做无差别删除。

最终应为一个对象，而非“内含 JSON 的字符串”。无需且不得对 JSON 结果再整体转义，不用渲染页面中的 HTML、MathML、复制文本或图片反向重建字段。没有实际运行工具时，不声称完成了程序校验。

### 网站与 Word 兼容边界

本规范约束的是生成内容的写法，不是前端渲染器或 Word 转换程序。统一源码、避免冗余表示和使用朴素结构，并不等于已经验证了具体网站的渲染、剪贴板行为或 Word 导出结果。

只有实际检查了对应流程，才能声称通过渲染或复制测试。若网站仍出现公式重复、源码显示、错行或复制异常，应基于实际 JSON、网页渲染结果和复制结果定位环节，不能仅凭现象认定是某个公式命令导致，也不能通过反复添加转义或临时切换定界方式掩盖问题。

格式检查在内部完成，不添加进题库的 `content`、`answer`、`category` 等字段，不随最终 JSON 附带规范引用或检查报告。
