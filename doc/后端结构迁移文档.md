## 1. 迁移结论

后端迁移目标为：

> **模块化单体（Modular Monolith）+ 业务域纵向组织 + 模块内轻量分层**

不采用微服务，也不为每个模块强行增加 Domain、Port、Adapter、Factory 等抽象层。

P1～P4 先保留 `app` 根包完成模块归位，避免同时调整业务目录和运行入口。用户确认上一阶段测试后，P5 已单独迁移到可安装的 `src` 布局：

```text

```

## 2. 当前基线与已确认事实

- Python 要求为 `>=3.12`。

## 3. 迁移原则

### 3.1 公开行为不变

第一阶段只调整内部结构，不改变：

- API URL、HTTP 方法和响应字段；
- 前端当前使用的请求参数和字段命名；
- 数据库表名、字段名和现有约束；
- 图片持久化相对路径规则；
- JWT 登录和管理员权限行为。

P5 后由 `src/web408/api/router.py` 作为路由组合入口，通过模块路由注册现有前缀，例如 `/auth`、`/subject`、`/exam`、`/mock` 和 `/upload`。只切换 Python 包名和启动入口，不调整 HTTP 契约。

### 3.2 单向依赖

```text
Router
  ↓
Query Service / Command Service
  ↓
Repository / 其他模块公开 Service / Storage
  ↓
Database / 文件系统
```

必须遵守：

- Router 不直接查询数据库或提交事务。
- Schema 不查询数据库、不判断权限、不调用外部服务。
- Repository 不调用 Service，不提交或回滚事务。
- Command Service 或跨模块 Workflow 拥有事务边界。
- 模块之间不得直接引用对方的 Repository 或私有实现。
- 目录、统计、媒体和题库之间的跨模块读取统一通过公开 Service、只读 DTO 或原生计数结果，不直接查询其他模块模型。
- `exam/read_service.py`、`mock/read_service.py` 只依赖各自 Repository，供目录用例读取引用及计数；题库 Query Service 可以依赖 `CatalogReadService`，但底层 Read Service 不反向依赖目录，避免用例互调形成循环。
- `ExamQuestion` 与 `MockQuestion` 保持独立实体，只共享题目内容规则、序列化和校验。
- `core/` 和 `database/` 不依赖业务模块。
- 不创建没有实际职责的空文件和空目录。
- 不创建万能 `common/utils.py`、通用 Repository 基类或过早的接口层。

### 3.3 事务与异常

- 一个业务用例对应一个事务边界。
- 写入 Service 使用显式事务，Repository 只执行持久化操作。
- 查询 Service 不提交事务。
- 业务异常由全局异常处理器统一映射，路由不重复编写相同的 `try/except`。
- 文件写入使用临时文件和原子替换；文件系统操作失败时清理临时文件。

## 7. 统计、媒体与跨模块协作

### 7.1 统计与导出

统计和导出虽然当前部分路由位于 `/exam`，实现上应归属 `reporting`：

- `exam` 提供题目读取能力；
- `catalog` 提供分类树和目录顺序；
- `reporting` 负责分类统计、去重口径和导出格式；
- 为兼容前端，原有 `/api/exam/category-stats` 和 `/api/exam/export-category-stats` 路径可以继续由组合路由注册。

P3-A 已将统计聚合、Markdown/Excel 导出和真题 Markdown 导出迁入 `src/web408/modules/reporting/`；`src/web408/modules/exam/router.py` 保留题库接口，组合路由继续注册原有 `/api/exam` 路径。reporting 通过 `ExamQueryService` 和 `CatalogReadService` 的只读 DTO 获取题目与目录数据。

统计规则保持现有文档定义：题目 ID 去重数、分类引用数、章节子树汇总数和未归档分类分别表达。

### 7.2 图片资源

将当前 `UploadService` 拆为三个职责：

1. `media/service.py`：上传、删除、清理等业务用例；
2. `integrations/local_file_storage.py`：安全路径、临时文件、原子替换和文件读写；
3. `media/reference_reader.py`：读取真题和模拟题文本并判断引用关系。

P3-B 已将上传路由、媒体 Service、图片引用读取和本地文件存储迁入 `src/web408/modules/media/` 与 `src/web408/integrations/local_file_storage.py`；media 通过 `ExamQueryService`、`MockQueryService` 的只读 DTO 扫描引用，不直接访问题库 Repository。媒体模块不得直接修改题目内容，也不得把图片删除结果当成题目更新操作。

## 8. 数据库迁移策略

### 8.1 第一阶段：只重组代码

- 保留现有表名、字段名、外键和唯一约束。
- 保留题目选项和分类 JSON 存储格式。
- 只拆分 Model 文件和 Repository 所属位置。
- 不删除、覆盖或重建现有数据库。
- 不创建数据库迁移链。

### 8.2 第二阶段：可选的数据模型改造

长期建议将分类名称 JSON 改为关联表：

```text
exam_question_category(question_id, category_id)
mock_question_category(mock_id, category_id)
```

收益：

- 分类改名不会产生字符串孤立引用；
- 可以使用外键约束；
- 分类统计可直接使用 JOIN 和聚合；
- 不再依赖 JSON 字符串 `LIKE` 查询。

该改造会改变数据库结构，必须单独编写数据方案。实际删除或重建数据库前，需要明确数据库绝对路径、数据损失范围、重建方式和检查方式，并获得用户授权。
