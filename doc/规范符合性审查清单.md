# 408Web 规范符合性审查清单

## 1. 审查说明

- **审查范围**：`backend-fastapi`、`frontend`、数据库结构及项目文档。
- **审查日期**：2026-09-05。
- **主要依据**：
  - `规范文档/后端规范文档.md`
  - `python-spec`：项目结构、FastAPI 契约、Pydantic、数据库事务、安全日志规范
  - `vue-ts-spec`：TypeScript Vue 组件、API 错误处理、异步状态、安全和交付规范
- **审查方式**：静态代码和配置审查，结合前端边界测试、后端模型检查及隔离浏览器回归；真实数据写入链路未全部执行。
- **状态说明**：`待修复` 表示当前仍不符合规范；`已授权例外` 表示存在规范差异，但由用户明确要求覆盖。

## 2. 高优先级问题

### 2.1 Markdown、SVG 和 KaTeX 渲染存在潜在 XSS

- **状态**：待修复
- **位置**：
  - `frontend/src/components/basic/MarkdownViewer.vue:49,145`
  - `frontend/src/components/basic/MarkdownEditor.vue:65`
  - `frontend/src/components/basic/config/xssWhitelist.ts:137`
- **现状**：开启了 `html: true`，KaTeX 使用 `trust: true`；SVG 代码块直接拼接原始内容，白名单允许 `href`、`xlink:href`、`style`、`target` 等属性。
- **影响**：恶意题目内容或导入数据可能构造脚本、危险链接或恶意 SVG。
- **整改方向**：关闭不必要的原始 HTML 和 KaTeX trust；SVG 采用严格解析和属性/协议白名单；渲染结果必须经过可信 Sanitizer。所有 `window.open(..., '_blank')` 调用增加 `noopener,noreferrer`。

### 2.2 前端错误日志可能泄露敏感信息

- **状态**：待修复
- **位置**：
  - `frontend/src/api/request.ts:38,66`
  - `frontend/src/views/user/Login.vue:150`
  - `frontend/src/views/user/Register.vue:218`
  - 其他页面多个 `console.error(error)` 调用
- **现状**：直接输出 Axios 错误对象。
- **影响**：错误对象可能包含 Authorization、登录密码、请求体和接口地址。
- **整改方向**：只记录脱敏后的错误类型、HTTP 状态码和 request ID；生产环境移除敏感控制台日志。

### 2.3 前端响应字段映射

- **状态**：已修复（2026-09-05）
- **位置**：
  - `frontend/src/api/request.ts:53-62`
  - `frontend/src/views/admin/ImageManage.vue:44-45`
  - `frontend/src/components/business/MockEditDialog.vue:371`
- **现状**：`request.ts` 在 JSON 响应边界统一执行 snake_case → camelCase 转换；`ImageManage.vue` 使用 `lastModified`，`MockEditDialog.vue` 按 `{ sources: [...] }` 读取来源；分类统计页面也使用驼峰字段。
- **验证**：API 边界测试覆盖嵌套字段、空分类和来源结构；隔离浏览器回归确认图片列表、模拟题编辑来源和分类统计可读取。
- **后续约束**：新增接口继续在 API 模块声明 DTO 并完成边界转换，页面不得再读取后端 snake_case 字段。

### 2.4 分类统计导出使用不存在的旧接口

- **状态**：待修复
- **位置**：`frontend/src/views/admin/ExamCategoryStats.vue:192`
- **现状**：仍通过 GET 和 Query 参数访问 `/api/exam/category-stats/export`，后端没有该路由。
- **影响**：统计导出功能必然失败，也违反 POST-only 和无 Query 参数规范。
- **整改方向**：明确导出需求后新增 POST Request Schema 和后端导出接口，或移除未实现的导出选项。

### 2.5 事务边界由数据库依赖隐式提交

- **状态**：待修复
- **位置**：`backend-fastapi/app/database/connection.py:63-80`
- **现状**：`get_async_session()` 和 `get_session_context()` 在 `yield` 返回后自动执行 `commit()`。分类写路由已改用函数级 `CategoryWriteSession`（`Depends(get_async_session, scope="function")`），提交发生在成功响应发送前，但提交动作仍由连接依赖隐式完成，问题方向不变。
- **影响**：依赖层隐藏写操作提交，业务用例无法明确声明事务边界，复用 Service 时容易出现不可预期提交。
- **整改方向**：依赖只负责创建和关闭 Session；由 Service/Use Case 使用明确的事务上下文管理提交和回滚。

### 2.6 查询存在 N+1、无界列表和全表内存扫描

- **状态**：待修复
- **位置**：
  - `backend-fastapi/app/services/exam_service.py:119,588,671,746,843`
  - `backend-fastapi/app/services/mock_service.py:83,542,622`
  - `backend-fastapi/app/services/category_service.py:359`
  - `backend-fastapi/app/services/upload_service.py:111,218`
- **现状**：题目响应转换时逐条查询科目和作者；分类统计按科目重复查询；年份、索引、来源和分类查询存在无分页限制；图片引用扫描读取全部题目并进行内存嵌套匹配。
- **影响**：数据量增加后请求耗时、数据库连接占用和内存消耗显著上升。
- **整改方向**：使用 JOIN/批量查询或 `selectinload`；为列表接口增加分页或明确上限；统计尽量下推数据库聚合；图片引用建立可扩展的索引或限制扫描范围。

## 3. 中低优先级问题

### 3.1 `pyproject.toml` 与依赖、命名空间包配置仍不完全一致

- **状态**：部分修复，仍待处理
- **位置**：`backend-fastapi/pyproject.toml`、`backend-fastapi/requirements.txt`
- **现状**：`pyproject.toml` 已声明运行依赖并生成 `uv.lock`，但 `requirements.txt` 仍维护另一份未锁定的依赖清单；删除 `__init__.py` 后仍没有显式源码包或构建配置。
- **影响**：不同安装入口可能解析出不同版本；使用构建工具安装隐式命名空间包时可能无法正确打包。
- **整改方向**：确定唯一依赖管理方式，并在需要构建时显式声明 namespace package；避免 `requirements.txt`、`pyproject.toml` 和锁文件长期分叉。

### 3.2 Pydantic v2 和时间类型仍有旧写法

- **状态**：待修复
- **位置**：
  - `backend-fastapi/app/models/base.py:15-22`
  - `backend-fastapi/app/models/entities.py:226,242-245`
- **现状**：使用 `class Config`、`datetime.utcnow` 和无时区时间。
- **影响**：产生兼容性/弃用警告，跨时区部署时容易出现时间解释不一致。
- **整改方向**：使用 `ConfigDict`；统一使用带时区的 UTC 时间，并统一序列化规则。

### 3.3 成功响应没有唯一构造入口

- **状态**：待修复
- **位置**：`backend-fastapi/app/schemas/common.py:34-53`
- **现状**：定义了 `success_response()`，但路由普遍直接实例化 `ApiResponse`；错误响应使用另一套 `error_response()`。
- **影响**：响应 Envelope 的构造逻辑分散，后续容易出现字段或成功码不一致。
- **整改方向**：提供并统一使用类型安全的 `success()` / `error()` 构造函数；移除无用的 `Response` 兼容别名。

### 3.4 日志配置和日志内容不符合完整规范

- **状态**：待修复
- **位置**：`backend-fastapi/app/utils/logger.py`
- **现状**：`settings.logging` 中的目录、文件名和轮转参数没有实际接入；日志没有 request ID/trace ID；多个 Service 大量记录 started/completed 日志。
- **影响**：配置修改不生效，日志难以关联请求，日志噪声较大。
- **整改方向**：统一从 Settings 创建日志；引入 request ID；只记录关键业务里程碑和失败事件。

### 3.5 JWT 生命周期治理仍不完整

- **状态**：待修复
- **位置**：`backend-fastapi/app/utils/security.py`、`frontend/src/utils/token.ts`
- **现状**：已验证签名、过期时间和 `sub`，但没有密钥轮换、Refresh Token、撤销策略或明确的 issuer/audience 策略；前端 Token 存在 `localStorage`。
- **影响**：密钥泄露或 XSS 后的 Token 管理能力有限。
- **整改方向**：根据威胁模型设计密钥轮换和注销策略；生产环境轮换旧密钥；评估 HttpOnly Cookie 或其他更安全的会话存储方式。

### 3.6 已跟踪数据库备份包含其他账号

- **状态**：待修复
- **位置**：`backend-fastapi/data/web408.db.backup`
- **现状**：当前运行数据库已只保留 `admin` 管理员，但已跟踪的备份仍包含 `admin1` 账号。
- **影响**：仓库分发或恢复旧备份时会重新带回已删除账号及其凭据哈希。
- **整改方向**：按数据保留要求决定是否更新、脱敏或移除该备份；同时检查 Git 历史中的敏感数据。

### 3.7 前端请求错误、竞态和测试覆盖不足

- **状态**：待修复/未验证
- **位置**：`frontend/src/api/request.ts` 及多个列表、统计和编辑页面
- **现状**：请求层仍未引入统一 `AppError`，业务错误主要表现为普通 `Error`；页面仍存在直接记录 Axios 错误和重复 Toast 的可能，筛选/快速切换也未全面使用 AbortController 或最新请求保护。`package.json` 已有 `test` 脚本和 24 项边界测试，但没有 Lint 脚本。
- **影响**：调用方无法稳定按错误类型处理，旧请求可能覆盖新数据；自动测试已覆盖 API、业务数据、存储和组件边界，但不能替代真实写入或完整端到端验证。
- **整改方向**：在请求层规范化错误并保留 status/code；区分取消、权限和业务错误；为列表请求增加取消/序列号保护；补充关键 API、权限和表单回归测试。

### 3.8 文档中的目标接口与实际接口需要明确区分

- **状态**：已修复（2026-09-05；目标与当前边界已分段）
- **位置**：
  - `doc/模块/题库内容维护模块开发设计.md`
  - `doc/模块/图片资源治理模块开发设计.md`
- **现状**：模块设计文档已补充“当前已实现边界”和“目标契约”分段，但目标表仍保留 `/create`、`/update`、`/query-detail` 等规划路径；它们不能当作当前路由调用。当前真实路径和 TypeScript API 入口已记录在迁移验证文档及项目结构导航中。
- **影响**：目标路径仍可能被误认为可调用接口，阅读时必须以“当前已实现边界”和实际源码为准。
- **整改方向**：后续实现目标接口时继续同步当前边界、Request Schema、前端 API 文件和验证记录；未实现接口保持“目标/待确认”标注。

## 4. 已符合的重点项

- 后端业务路由已统一使用 POST。
- 后端未发现 `Query()` 查询参数。
- 普通 JSON 请求使用 Request Schema。
- 业务响应已统一为 `{code, message, data}`，列表内部使用 `lists/pagination`。
- JWT 默认密钥已移除，密钥改由环境变量提供。
- 图片接口已加入管理员鉴权、扩展名/MIME/文件头/大小校验和引用保护。
- 运行数据库已完成数据保留型迁移，题目作者关联无孤儿记录。
- 项目中已移除全部 `__init__.py` 文件。
- 前端 TypeScript 迁移已完成：应用源码无 `.js` 文件，Vue SFC 均使用 `lang="ts"`；类型检查、构建和 24 项边界测试已执行，详见 `doc/前端TypeScript迁移验证.md`。
