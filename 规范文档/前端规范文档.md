# 前端规范

> 前端开发规范由 skill `vue-ts-spec`（TypeScript 项目）或 `vue-spec`（JavaScript 项目）承载，通过 skill 按需加载对应模块的规范文件，避免全量读取。规范原文随 skill 分发，不依赖具体机器、操作系统或项目目录，可随 skill 在任意环境中使用。

## 使用方式

前端开发任务会自动触发对应 skill，skill 会根据任务类型按需加载对应的 reference 文件。

## 全局速查（通用规则）

1. Composition API：使用 `<script setup>`，不用 Options API
2. 路由懒加载：`() => import()` 动态导入
3. Props：优先使用类型声明 `defineProps<Props>()`；需要运行时校验、泛型或保留多种原生值类型时可使用运行时声明配合 `PropType`。默认值使用 Vue 3.5 响应式解构或 `withDefaults()`。
4. Emits：显式声明事件；脚本内事件名用 camelCase，模板监听用 kebab-case；`update:modelValue` 等 v-model 协议保持 Vue 约定
5. 语义化标签：header/nav/main/section/footer，一个页面一个 `main`；不设机械层级上限，嵌套影响理解或复用时拆分
6. 完整异步状态：覆盖加载、空、错误、重试、取消、重复提交和旧响应覆盖，区分首次加载/后台刷新/提交/局部更新
7. 统一请求入口：不自行创建 Axios 实例；错误按项目请求层及错误工具处理，保留必要的后端提示
8. 动态 Tailwind 类名：用完整静态映射，禁止 `bg-${color}` 拼接
9. 可访问性：优先原生语义元素、键盘可操作、具备可访问名称，管理焦点与状态播报
10. 性能按证据优化：先测量，再使用虚拟列表、`shallowRef`、`v-memo` 或分包
11. 验证后交付：运行仓库已有的格式化、类型检查、Lint、测试和构建命令，如实报告结果

## 当前项目约定

1. Vue 3 + TypeScript，Vue 组件使用 `<script setup lang="ts">`；应用配置启用 `strict: true`、`allowJs: false`。
2. 延续现有自定义组件与 Element Plus；图标使用已安装的 FontAwesome 7，样式采用 Tailwind CSS 4。
3. API 出站字段使用 snake_case，前端调用参数和响应模型使用 camelCase；`api/request.ts` 统一校验 `{code, message, data}` 信封，`code === 200` 为成功，文件下载使用独立 Blob 响应入口。
4. `api/request.ts` 的 JSON 入口返回 `ApiResponse<T>`，文件下载使用 `requestBlob` 保留 Blob 与响应头。当前错误处理使用 Axios 错误收窄和 `utils/errors.ts`，未引入 AppError 类。
5. 公共业务类型放在 `src/types/`，题目编辑和导入类型放在 `composables/questionFormTypes.ts`；外部 JSON、localStorage 和路由参数必须经过校验或收窄。
6. `npm run type-check` 检查应用及 Vite 配置；`npm test` 运行 Node 内置测试；`npm run build` 先检查类型再构建。仓库未配置 Lint 脚本，不得声称已通过 Lint。
7. Node 要求为 `^20.19.0 || >=22.12.0`，依据已安装 Vite 7 的 engines。PostCSS/Tailwind 工具配置和 `.mjs` 测试不属于应用 JS 源码。
8. 测试覆盖 API、业务数据和组件事件，真实页面回归结果须另行记录，不将模拟测试描述为浏览器全通过。

9. 题目选项固定为 A-D 字符串键；递归命名转换不得把这些键改为小写或其他形式。外部 JSON、localStorage、路由查询和响应数据均须在进入业务状态前完成运行时收窄。

## 约定优先级

发生冲突时按以下顺序处理：

1. 用户本次明确要求
2. 仓库级指令与项目文档（如项目 CLAUDE.md）
3. `package.json`、构建配置、类型配置、Lint 配置和真实接口契约
4. 同模块已有实现与共享组件
5. skill 推荐规则
