# 408Web 项目结构

本文说明当前实现的运行边界、目录职责与业务模块，是按任务定位代码的入口，不是目录重构方案或未来架构设计。

## 阅读方式与范围

- 路径基准：仓库根（`408web/`），文中源码路径均相对此根。
- 覆盖：`frontend/`（Vue 3 SPA）、`backend-fastapi/`（FastAPI 服务）、根目录启动脚本、`README.md`、`doc/题目/`（题目录入规范）。
- 排除：`backend-fastapi/.venv`、`backend-fastapi/data`、`backend-fastapi/uploads`、`backend-fastapi/logs`、`frontend/node_modules`、`frontend/dist`（运行时数据、依赖与构建产物，只在资源边界中登记）；`.agents/`（项目记忆与 Skill）不算业务实现；`.docx` 样例文件与 `后续开发任务.md` 属资料，不纳入模块划分。
- 阅读顺序：总览 → 目标模块 → 该模块实际引用的[公共记录](modules/shared.md)。
- 每个文件只在一个位置归属；跨模块引用不改变所有权，逻辑模块划分不等同物理目录。

| 侧 | 事实来源 | 当前形态 |
| --- | --- | --- |
| 前端 | `frontend/package.json`、`frontend/vite.config.ts`、`frontend/tsconfig.app.json` | Vue 3 + TypeScript（`strict`、`allowJs: false`）、Vite 7（监听 `0.0.0.0:7784`，代理 `/api`、`/uploads` 到 7785）、Vue Router 4、Pinia 2、Tailwind CSS 4（PostCSS）、自研基础组件、FontAwesome 6、markdown-it + KaTeX + xss、`@kangc/v-md-editor`、axios、html-to-image |

## 运行与调用边界

```text
浏览器
  │  HTTP（统一 POST + ApiResponse{code,message,data}）
  ▼
前端 Vite 开发/预览服务器 :7784 ──(代理 /api、/uploads)──► FastAPI 服务 :7785
  │                                                        │
  └─ 静态资源 /uploads/images ◄── 同源代理 ─────────────────┘（StaticFiles 挂载同一目录）
                                                           │
                                                   SQLite data/web408.db
                                                   uploads/images/
                                                   系统私有目录中的 AI 主密钥
```

| 单元／公开入口 | 源码与装配位置 | 职责 | 通信／调用与生命周期 |
| --- | --- | --- | --- |
| 前端 SPA | `frontend/index.html` → `frontend/src/main.ts` → `frontend/src/App.vue` → `frontend/src/app/layouts/AppShell.vue`；构建配置 `frontend/vite.config.ts` | 阅读端与管理端全部页面、路由守卫、axios 拦截器、全局导航与 AI 客服窗 | 由浏览器加载；`VITE_API_BASE_URL` 为空时走同源相对路径 `/api`，否则直连后端并依赖 `CORS_ORIGINS` |
| 后端 API 进程 | `backend-fastapi/src/web408/main.py`（ASGI：`web408.main:app`）；路由聚合 `backend-fastapi/src/web408/api/router.py` | 提供 `/api/*` 业务接口、`/uploads/images` 静态文件、`/` 与 `/health` 健康检查 | `lifespan` 内先 `init_db()` 补建缺失表，再 `AiRuntime.startup()`；关闭时依次 `AiRuntime.aclose()`、`engine.dispose()` |
| 后端进程内 AI 运行模块 | `backend-fastapi/src/web408/modules/ai/runtime/manager.py`（`AiRuntime`） | 内置型号目录、模型检测互斥、咨询会话、生成位与闲置回收 | 不是独立进程、不监听端口；会话只存在内存，进程重启即丢失 |
| 启动脚本 | `startup-backend.bat` / `startup-backend.command`、`start-frontend.bat` / `start-frontend.command` | 切换到各自工作目录并校验虚拟环境或 `node_modules` 后启动 | 仅开发期便利脚本；后端必须以 `backend-fastapi/` 为工作目录，否则 `.env`、`data/`、`uploads/`、`logs/` 解析位置改变 |

后端所有业务接口统一使用 `POST`（含查询），异常经 `backend-fastapi/src/web408/core/exceptions.py` 映射为统一信封；CORS 由 `backend-fastapi/src/web408/middleware/cors.py` 的全局中间件注入，保证异常响应也带允许头。

## 关键数据流

### 分类阅读页取题（真题／模拟题／改编题同构）

用户在 `frontend/src/views/user/ExamClassify.vue`（模拟题 `MockClassify.vue`、改编题 `AdaptationClassify.vue`）选择科目与分类 → `composables/useInfiniteQuestionList.ts` 分页调用 `api/exam.ts#getExamList`（或 `api/mock.ts`、`api/adaptation.ts`）→ 后端 `modules/exam/router.py` 的 `POST /api/exam/query` → `ExamQueryService.get_paginated` 经 `ExamRepository` 查询 `exam_question`，并用 `CatalogReadService`、`CustomCategoryReadService` 展开分类子树名称、用 `AuthReadService` 补作者名 → `mapper.to_exam_response` 把 JSON 文本反序列化为选项与分类数组 → 前端按分类树分组（`utils/examCategoryGrouping.ts`）渲染并生成大纲锚点。

阅读页首次进入分类时会调用 `useInfiniteQuestionList` 的 `loadAll` 一次取全量，以便左侧大纲完整；跨页切换靠路由 `keepAlive` 保留状态。

### AI 题目咨询（流式）

在题目卡片上打开 `components/business/AiConsultationDialog.vue`（页面内唯一窗口，`composables/useAiConsultationPanel.ts` 协调）→ `POST /api/ai/sessions/create` → `AiConsultationService` 用认证账号重新读取该题目详情（`question_context.build_question_snapshot`）并登记图片引用，随后解密账号凭据、交给 `AiRuntime` 建立内存会话（此步不调用模型）→ `POST /api/ai/sessions/{id}/messages` 返回 `text/event-stream`，`ConsultationResponse` 转发 `meta` / `delta` / `done` 事件 → 前端 `api/aiSession.ts#streamAiMessage` 用 `fetch` + `ReadableStream` 解析（axios 不支持流式）→ 停止走 `POST /abort`（按 `request_id` 取消原请求）、离开走 `POST /close`；ASGI 调用结束时 `AiStream.aclose()` 兜底回收。

### 分类改名回写三类题目

管理员在 `views/admin/CategoryManage.vue` 或 `CustomCategoryManage.vue` 改名 → `POST /api/exam-category/{id}` / `POST /api/custom-category/{id}` → 对应 `CommandService` 在同一会话内调用 `modules/exam/category_tag_service.py`、`modules/mock/category_tag_service.py`、`modules/adaptation/category_tag_service.py`（自定义分类另走 `modules/exam/custom_category_tag_service.py`）逐个改写题目分类 JSON 中的名称，最后由 Command Service 统一提交。分类名称是持久标识，改名必须回写；移动分类不改变标签。

## 状态与资源边界

| 数据／资源 | 权威维护者 | 位置或定义来源 | 访问及生命周期边界 |
| --- | --- | --- | --- |
| 业务数据（16 张 SQLModel 表，另有 `schema_migrations` 与 `sqlite_sequence`） | 各模块 `models.py` 的 SQLModel 定义 | `DATABASE_URL`，默认 `backend-fastapi/data/web408.db`（WAL 模式，连接时开外键与 `busy_timeout`） | 每请求一个 `AsyncSession`（`database/connection.py`），读用例不提交、写用例由 Command Service 显式 `commit`；启动只 `create_all` 补建缺失表，无迁移脚本 |
| 题目分类标签 | `exam_question.category` / `custom_category`、`mock_question.category`、`adaptation_question.category`（JSON 数组文本） | 各模块 `models.py` | 存名称不存 ID；名称在科目内唯一；删除分类前须先摘标签（`ExamReadService.count_custom_category_references`） |
| 出题状态 | `mock_question_exam_mark`、`adaptation_question_exam_mark` | 各模块 `models.py`（题号唯一约束 + 级联删除） | 独立表保存，不改题目主体；仅管理员写 |
| 模拟题答错次数 | `mock_question_wrong_count` | `modules/mock/models.py` | 独立表；记录接口当前未要求认证，调整接口要求管理员 |
| 图片文件 | `modules/media/service.py`（`UploadService`）+ `integrations/local_file_storage.py` | `UPLOAD_DIR`，默认 `backend-fastapi/uploads/images/` | 落盘文件名随机化，`/uploads/images/<file>` 对外访问；删除过程图片只解除真题关联，物理文件进入未引用清理 |
| AI 主密钥 | `integrations/ai_local_secrets.py` | 系统用户私有目录下的 `408web/ai/`（Windows 为 `%LOCALAPPDATA%`） | 首次保存 Key 时生成；缺失或损坏时报错而不是重建；不进入数据库与响应 |
| AI 账号配置 | `user_ai_provider_config`、`user_ai_custom_model`、`user_ai_config` | `modules/ai/models.py` | API Key 以 Fernet 密文入库（`modules/ai/key_cipher.py`），每账号每供应商一份 |
| AI 咨询会话 | `modules/ai/runtime/session.py` 的进程内管理器 | 内存（上限：每账号 4 个、全局 128 个、每会话 12 轮、闲置 30 分钟回收） | 不落库、不落盘；进程重启丢失 |
| 前端登录态 | `frontend/src/stores/auth.ts` + `utils/token.ts` | `localStorage`（`web408_token`、`userInfo`） | Token 无过期时间，`isAdmin` 要求同时持有 Token 且角色为 `ADMIN`；401 时清 Token 并跳登录 |
| 浏览器本地偏好 | `composables/useFavorites.ts`、`composables/useMarkdownMediaResize.ts` | `localStorage`（收藏分类、Markdown 大图显示尺寸） | 纯本地，跨设备不共享 |
